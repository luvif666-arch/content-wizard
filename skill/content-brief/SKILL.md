# 内容创作简报

把「做内容就是跟一个人聊天」这件事固化成六个必须依次走完的问题。用户给出一个大方向，你负责一层层收窄，最后交出一份创作简报。

**这个技能不写成稿。** 它只负责把中间那层想清楚；写稿是拿到简报之后的下一步。这个边界很重要——直接出稿会让用户跳过思考，回到「收藏一堆选题但写不出来」的原点。

## 六个步骤

**一次只问一个问题。** 拿到这一步的答案之前，不要暴露下一步，也不要一次抛出全部六个问题。

| 步 | 层 | 你要问的 | 拿到什么 |
|---|---|---|---|
| 1 | 关系 | 这条内容是给谁看的 | 受众及其处境 |
| 2 | 话题 | 想聊哪个大方向 | 一个方向 + 收窄后的子话题 |
| 3 | 选题 | 这次对谁说什么 | 一个具体的人 + 一件具体的事 |
| 4 | 切入点 | 这次从哪里开始聊 | 1–3 个入口及顺序 |
| 5 | 标题 | 用哪句话开启这段对话 | 一句话 + 它邀请谁进来 |
| 6 | 表达 | 你准备用什么让对方理解 | 结构顺序 + 体裁 |

### 第 1 步 · 关系

问：「这条内容是给谁看的？」

给 4–5 个选项让对方选，或让他自己描述：完全陌生的人 / 已关注我的人 / 同行的从业者 / 潜在客户 / 熟人朋友。

选完用一句话点明这个选择的含义，例如选了「完全陌生的人」就说：「那需要从头建立语境，不能跳步，也不要假设他知道任何背景。」

### 第 2 步 · 话题

问：「你想聊哪个大方向？」

拿到大方向后，**必须给出更小的子话题供选择**，而不是直接往下走。给 4 个候选，让他选 1–2 个。

命中已知领域时用内置映射（见 `reference/presets.md`），没命中就按这个方向现推 4 个具体分支，并允许他自己写一个。

**如果对方只给了一个大方向就想继续，拦住他**：「这个话题还圈得太大，选一个更小的分支再往下。」

### 第 3 步 · 选题

这是全流程的核心。问：「这次你要对谁说什么？」

必须同时拿到**一个具体的人**和**一件具体的事**：

- 具体的人，从这些处境里选或自己描述：第一次做这件事的人 / 做过很多次却一直卡住的人 / 正在做选择的人 / 已经做了但结果不好、在怀疑自己的人
- 具体的事，写成一句「给【谁】，讲【怎么 / 为什么】」的话

缺任何一个都不要往下走，明确告诉他缺哪一半。

拿到之后，**主动替他生成一份「这次不讲什么」**，把范围外的内容列出来。这一步能省掉后面大量返工。

### 第 4 步 · 切入点

问：「这次从哪里开始聊？」

给六类各生成一个结合当前选题的具体入口：具体场景 / 普遍误区 / 一次踩坑 / 两类人对比 / 极小细节 / 一个时间点。让他选 1–3 个并排序。

**这一条必须守住**：切入点只负责把人带进来，后面的内容要继续完成第 3 步选定的目标。如果他选的都是「误区 / 踩坑 / 对比」这类纯信息型入口，明确提醒：这类入口能吸引人进来，但本身不指向结论，正文必须回到「对谁说什么」那个目标，否则会变成另一篇内容。

### 第 5 步 · 标题

按三种句式各给 **1 条**标题，**每条必须附一行理由**说明这句话在邀请谁进来、为什么他会想点开：

- 问题式：把读者正在做的那次选择直接摆出来
- 判断式：先给结论，正文负责解释为什么
- 共鸣式：从一个容易代入的失败经历开始

理由不能省略。只给三句干巴巴的标题等于没给。

### 第 6 步 · 表达

默认给三段结构：场景（让对方先认出现象）→ 解释（回答为什么值得在意）→ 具体建议（让对方下次做决定时用得上）。允许他增删改序。

再问体裁：图文 / 口播视频 / 多图轮播。选了视频或轮播，追加两个针对该体裁的问题，例如视频问「哪些地方需要画面演示、哪些段落可以剪短」。

## 产出

按 `reference/brief-format.md` 的格式输出创作简报，六个区块齐全。用 Markdown，让用户能直接复制走。

最后可以追加一句：这份简报可以直接发给任何 AI 让它按此写稿。

## 边界

- **不直接写成稿**，除非用户明确要求「顺便写出来」。
- **不替他决定选题**。你负责给候选、指出矛盾、提醒遗漏，最终选择权在他。
- **不编造他的经历**。简报里需要具体例子时，问他要，不要虚构。
- 六步是检查清单，不是流水线。如果他带着现成的标题或切入点来，就从他卡住的那一步接上，不要强迫他从第 1 步重走。
