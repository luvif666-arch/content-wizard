# 可直接发给 Agent 的需求（复制这一段即可）

> 用法：把下面「需求正文」整段复制，直接发给你的编程 Agent。如果它还缺信息，让它读同目录下的 `flow.json` 和 `需求与背景.md`。

---

## 需求正文

帮我做一个**纯前端的「内容创作向导」网页小程序**，把一篇文章的思维过程固化成固定步骤，用户一路点选就能得到一份能直接发给 AI Agent 的创作简报。

**一句话定位**：用户从一个大方向出发，向导一步一步帮他收敛到「对谁说什么、从哪里开始、用哪句话开口」，最后输出一份创作简报，而不是直接写成稿。

**技术约束**：
- 纯前端，不接后端服务；用 Vite + React + TypeScript。
- 所有 AI 能力通过一个可替换的适配层调用（默认走 OpenAI 兼容的 `/chat/completions`，API Key 由用户在设置页填写，存 `localStorage`）。
- 没有 API Key 或请求失败时，必须回退到内置预设库 + 规则模板，向导依然能从第一步走完最后一步。
- 中文界面。

**六个步骤，一次只显示一步，不能跳步**：

1. **关系**：单选，问「这条内容是给谁看的」，选项如"完全陌生的人 / 已关注我的人 / 同行 / 潜在客户 / 熟人"，并允许自定义。选完提示这句话帮助用户确立语境。
2. **话题**：用户自由输入一个大方向（如"情感"），系统给出 4 个子话题卡片供其选择，最多选 2 个。子话题优先从内置预设映射表取；没命中再调模型生成 6 个、去重后展示 4 个。必须允许用户自己输入子话题。如果用户没选就直接下一步，给出提醒而不是放行。
3. **选题**：两部分，必须都填。上半部分选「具体的人」（如"第一次做这件事的人 / 做过很多次却一直卡住的人 / 正在做选择的人 / 已在怀疑自己的人 / 自定义"）；下半部分填「具体的事」，写成一句"给【谁】，讲【怎么/为什么】"。填完后自动生成一张「这次不讲什么」的过滤清单。
4. **切入点**：先给 6 类切入点（具体场景 / 普遍误区 / 一次踩坑 / 两类人对比 / 极小细节 / 一个时间点）各生成一个结合当前选题的候选，用户选 1–3 个并排序。当选中的切入点无法通向第 3 步的目标时，必须显示警告并要求用户确认。
5. **标题**：按三种句式各生成 1 条——问题式、判断式、共鸣式，每条必须附一行「这句话在邀请谁进来、为什么他会想点开」。用户选 1 条或自己写。
6. **表达**：默认给「场景 → 解释 → 具体建议」三段结构，可增删改顺序；再选体裁（图文 / 口播视频 / 多图轮播），选视频或轮播时追加 2 个针对该体裁的追问。

**最终输出**：一屏创作简报，包含 关系 / 话题 / 选题（含不讲什么） / 切入点 / 标题（含理由） / 表达结构与体裁，提供「复制全文」「复制为 Agent 提示词」「导出 Markdown」「导出 JSON」「分享链接」五个动作。

**必须做到的状态规则**：
- 草稿自动存 `localStorage`，刷新不丢。
- 任意步骤可回退修改；**一旦改动上游，所有下游答案标记为「待确认」并要求用户重新确认**，不能静默沿用旧答案。
- 顶部显示进度（如 3/6），可点击已完成的步骤跳回。
- 移动端可用（单列布局，按钮不小于 44px 触控区）。

**验收标准（逐条可测）**：
- 不填 API Key 也能完整走完 6 步并导出简报。
- 输入"情感"，第 2 步能出现可选的子话题，而不是空白或报错。
- 第 3 步只填一半时无法进入第 4 步，并提示缺哪一半。
- 在第 3 步改掉"具体的人"后，第 4、5 步立刻显示待确认标记。
- 第 5 步每条标题都带一句生成理由，不是干巴巴三句话。
- 导出的 Markdown 与 JSON 内容一致、字段完整、可直接粘贴进另一个 AI 对话框使用。
- 断网且无 Key 时，全流程仍可走完，仅候选项来自预设而不是模型。

**明确不做**（避免范围膨胀）：
- 不做账号系统、不做云同步、不做多人协作。
- 不直接生成成稿或封面图。
- 不接入任何平台的实时热榜数据。

**交付顺序**：先做能跑通 6 步 + 导出简报的版本（模型层可先只接预设库），确认流程顺畅后再接模型生成候选。
