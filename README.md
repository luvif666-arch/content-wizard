# 内容创作向导 · Content Wizard

把一个宽泛的内容方向，一步步收敛成**「对谁说什么、从哪里开始、用哪句话开口」**。

起因是一篇文章：《如果你做不好内容，大概率也聊不好天》。它说做内容就是跟一个人聊天——先看对面坐着谁，再找共同话题，然后挑他正在经历的事，按他知道多少决定从哪接话。这套判断很适合固化成固定步骤，于是就有了这个项目。

**在线使用**：<https://luvif666-arch.github.io/content-wizard/>

---

## 这个仓库里有什么

| 目录 | 内容 |
|---|---|
| [`web/`](web/) | 网页版：纯前端六步向导，点着走完就能拿到一份创作简报 |
| [`skill/`](skill/) | Agent Skill 版：同一套流程，装进 Claude Code / Codex 等 Agent 直接用 |

网页版和 Skill 版**共用同一套流程定义**（`docs/flow.json`），不是两份各自维护的实现。

## 快速开始

### 网页版

直接打开 <https://luvif666-arch.github.io/content-wizard/> 就能用，不需要登录，也不需要 API Key。

本地跑：

```bash
cd web
npm install --ignore-scripts
npm run build
npm run serve        # http://127.0.0.1:5240/
```

不填 API Key 时，所有候选项来自内置预设库，**断网也能完整走完六步**。填了之后第 2、4、5 步的候选改由你配置的模型生成，调用失败自动回退。

### Skill 版

把 `skill/content-brief/` 整个目录放进你 Agent 的 skills 目录（例如 Claude Code 的 `~/.claude/skills/`），之后说「我想做一条关于 XX 的内容」就会触发。

## 六步做什么

| 步 | 层 | 你要回答的 | 得到什么 |
|---|---|---|---|
| 1 | 关系 | 这条内容是给谁看的 | 受众及其处境 |
| 2 | 话题 | 你想聊哪个大方向 | 方向 + 收窄后的子话题 |
| 3 | 选题 | 这次你要对谁说什么 | 具体的人 + 具体的事 + 「这次不讲什么」 |
| 4 | 切入点 | 这次从哪里开始聊 | 1–3 个入口及顺序 |
| 5 | 标题 | 用哪句话开启这段对话 | 一句话 + 它邀请谁进来 |
| 6 | 表达 | 你准备用什么让对方理解 | 结构顺序 + 体裁 |

终点是一份**创作简报**，不是成稿。它可以直接复制给任何 AI 让它按此写稿，也可以导出 Markdown / JSON 留档——JSON 能再粘回来继续改。

## 两个设计上的关键选择

**候选生成预设优先、模型兜底。** 候选项按「内置预设库 → 规则模板 → 模型生成」的顺序取，任何一环失败都往下回退。所以没有 Key、甚至断网，流程照样能走完。界面上会如实标注候选来源，不假装查过。

**改上游必须让下游重新确认。** 每一步确认时会存下「它当时依赖的上游答案」快照。之后上游一变，这一步就标记为待确认，进入时要求重新确认，不静默沿用旧答案。判据是「这一步有没有确认过的快照」，而不是「本次会话走到哪」——否则刷新页面后，已确认的下游会被静默当成仍然有效。

## 验收

网页版带一份端到端验收脚本，用真实 Chrome 走完整流程并逐条核对，当前 **41 / 41 通过**：

```bash
cd web
npm run serve        # 另开一个终端
npm run verify
```

验收过程中发现并修掉的真实缺陷包括：第 2 步话题未回写父状态、拦截提示跨步骤残留、刷新后漏报「待确认」。细节见 [`web/README.md`](web/README.md)。
